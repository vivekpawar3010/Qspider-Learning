Semantic Tags

Definition:
Semantic HTML tags provide meaning to the content they wrap. They tell both browsers and developers the significance of the content.
Advantages of Use:
✓ Improved SEO - Search engines better understand page content
✓ Better Accessibility - Screen readers can interpret content structure
✓ Easier Maintenance - Code intent is clear to developers
✓ Better Code Organization - Logical structure is evident
✓ Mobile Friendly - Proper semantics help responsive design

Header Tag (<header>)

What it contains: Introductory content, navigation, logo, and branding information

When to use: At the top of pages or sections to group heading, logo, and navigation

Example usage: Company logo, main navigation menu, search bar

Semantic benefit: Search engines know this is important introductory content

Main Tag (<main>)

What it contains: The primary content of the document

Important rule: Should appear only ONCE per page

When to use: Wrap all the main content excluding header, footer, and sidebars

Example usage: Blog post, article content, product details

Semantic benefit: Screen readers and search engines identify the main content area immediately

Section Tag (<section>)

What it contains: Thematically related content grouped together

How it works: Used to organize page content into logical sections

When to use: When you have related content that belongs in one block (like chapters, tabs, or content groupings)

Example usage: "Introduction section", "Features section", "Testimonials section"

Semantic benefit: Clearly marks different topics or areas within your main content

Article Tag (<article>)

What it contains: Self-contained, independent content that could stand alone

Key characteristic: Should be independently distributable and reusable

When to use: Blog posts, news articles, forum posts, user comments, product reviews

Example usage: Blog post, news story, review, podcast episode description

Can be nested: Articles can contain sections, and sections can contain articles

Semantic benefit: Search engines and readers know this is complete, standalone content

Footer Tag (<footer>)

What it contains: Footer metadata, copyright, links, and contact information

When to use: At the bottom of pages or sections to group ending content

Example usage: Copyright notice, contact info, related links, sitemap, social media links

Can be used multiple times: Each section or article can have its own footer

Semantic benefit: Clearly marks the end of content and provides important document information

Non-Semantic Tags (Generic Containers)

What are Non-Semantic Tags?

Non-semantic tags are generic HTML elements like <div> and <span> that have NO built-in meaning.

They are purely for styling and layout without indicating what the content represents.

Difference Between Semantic and Non-Semantic

SEMANTIC: <header> tells you "this is a header" - has meaning

NON-SEMANTIC: <div> tells you nothing about the content - no meaning

When to use Non-Semantic Tags?

When no semantic tag fits your needs perfectly

For styling and layout that semantic tags don't cover

As a fallback when semantic alternatives don't exist

Problems with Non-Semantic Tags

Poor SEO:
Search engines can't determine what content is important or what it represents
Reduced Accessibility:
Screen readers for visually impaired users get no context about the content
Unclear Intent:
Other developers (and you in 6 months) won't understand the purpose of the markup
Higher Maintenance:
You must rely on class names and comments to explain structure
Less Meaningful:
Code doesn't explain itself - requires additional documentation

Examples of Non-Semantic vs Semantic

OLD WAY (Non-semantic): <div class="header">...</div>

NEW WAY (Semantic): <header>...</header>

OLD WAY (Non-semantic): <div class="article">...</div>

NEW WAY (Semantic): <article>...</article>
